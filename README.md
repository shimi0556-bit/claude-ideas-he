## 1. הקדמה קצרה + איך להשתמש במסמך

Claude (של Anthropic) הוא עוזר שפה חזק במיוחד בטקסט ארוך, ניתוח מעמיק, כתיבה מובנית, וקוד. מעבר לצ׳אט הרגיל יש אקוסיסטם שלם:

| כלי | מה זה בקצרה | מתי להשתמש |
|---|---|---|
| **Claude.ai** | ממשק הצ׳אט הראשי | שיחות, כתיבה, ניתוח, Artifacts |
| **Projects** | מרחב עם ידע קבוע + הוראות | פרויקט מתמשך עם מסמכים/קונטקסט |
| **Artifacts** | תוצר עצמאי ליד הצ׳אט (מסמך, אפליקציה, דשבורד) | כשרוצים לערוך/לשתף/לאיטרציה |
| **Skills** | תיקיות הוראות (`SKILL.md`) שנטענות לפי צורך | תהליכים חוזרים ומומחיות ניידת |
| **MCP** | חיבור לכלים חיים (Drive, Slack, GitHub וכו׳) | כשצריך נתונים/פעולות בזמן אמת |
| **Claude Code** | סוכן בקוד/טרמינל עם קבצים, גיט, סאב־סוכנים | פיתוח, ריפקטור, אוטומציה מקומית |
| **Computer use** | שליטה בשולחן עבודה (צילום מסך, קליקים) דרך API | אוטומציה של ממשקים גרפיים (**API / סביבה מבוקרת**) |
| **Subagents** | סוכנים עם הקשר וכלים נפרדים | פיצול משימות + בידוד הקשר |

### איך לקרוא את המסמך
1. התחילו ב־**תוכן העניינים** וקפצו לקטגוריה הרלוונטית.
2. לכל רעיון: קראו את **איך להתחיל** לפני שתעתיקו פרומפט.
3. אם חוזרים על אותן הוראות — הפכו אותן ל־**Skill** או להוראות **Project**.
4. אם צריך נתונים חיים — חברו **MCP**; אל תעתיקו ידנית שוב ושוב.
5. רמות קושי: 🟢 קל · 🟡 בינוני · 🔴 מתקדם.

### דפוס פרומפט מומלץ (RCTFC + דוגמאות)
למשימות מורכבות השתמשו בתגיות XML (Claude עובד איתן היטב):

```xml
<role>עורך טכני בעברית ברורה</role>
<context>קהל: מפתחים מתחילים. מוצר: אפליקציית ניהול משימות.</context>
<task>כתוב מדריך התקנה בן 800–1200 מילים</task>
<format>Markdown עם כותרות H2/H3, רשימות ממוספרות, ובלוק פקודות</format>
<constraints>
- בלי זargon מיותר
- כל שלב חייב להיות ניתן לביצוע תוך דקה
- אם חסר מידע — שאל שאלה אחת במקום לנחש
</constraints>
<examples>
דוגמה לסגנון: "פתחו טרמינל והריצו: npm install"
</examples>
```

**כלל אצבע:** פרומפט חד־פעמי → פרומפט. חוזר בין שיחות → Skill. רקע קבוע לפרויקט → Project. גישה לכלים חיים → MCP.

## 3. מיפוי כלים — מה לבחור מתי

| צורך | בחירה ראשונה | שילוב חזק |
|---|---|---|
| רקע קבוע (מותג, מוצר, לקוח) | **Project** | Project + Skill לפורמט דוחות |
| שיטת עבודה חוזרת | **Skill** (`SKILL.md`) | Skill + MCP לנתונים |
| חיבור ל־Gmail/Slack/Drive/DB | **MCP** | MCP + Skill לנהלים |
| תוצר לעריכה/שיתוף | **Artifact** | Artifact + MCP לדשבורד חי |
| עבודה על ריפו מקומי | **Claude Code** | Code + Skills + Subagents |
| משימה מסוכנת (דיפלוי) | Skill עם `disable-model-invocation: true` | הפעלה ידנית ב־`/skill-name` |

מקורות רשמיים מומלצים: [Skills explained](https://claude.com/blog/skills-explained), [Artifacts Help](https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them), [anthropics/skills](https://github.com/anthropics/skills), [hoodini/ai-agents-skills](https://github.com/hoodini/ai-agents-skills) (Yuval Avidani).

## 4. כתיבה ועריכה

### 1. עריכת סגנון לפי מדריך מותג
- **מה עושים:** מעלים מדריך סגנון (טון, מילים אסורות, דוגמאות) ל־Project ומבקשים לערוך טקסטים בהתאם.
- **למה שימושי:** עקביות בין דפי נחיתה, מיילים ופוסטים בלי לחזור על אותן הוראות.
- **איך להתחיל:**
  1. צרו Project בשם «Brand Voice».
  2. העלו PDF/Markdown של מדריך הסגנון + 3 דוגמאות טובות.
  3. הוסיפו הוראת פרויקט: «תמיד שמור על טון חם־מקצועי; אל תשתמש בסימני קריאה מרובים».
  4. פרומפט: `ערוך את הטקסט הבא לפי מדריך הסגנון בפרויקט. החזר טבלה: לפני | אחרי | סיבת השינוי.`
- **כלים:** Claude.ai · Projects
- **קושי:** 🟢

### 2. סיכום ארוך עם מבנה קבוע
- **מה עושים:** מסכמים מאמר/דוח לפי תבנית (תקציר מנהלים → נקודות מפתח → סיכונים → המלצות).
- **למה:** חוסך קריאה של עשרות עמודים ומכריח פלט שמיש להחלטה.
- **איך להתחיל:**
```xml
<task>סכם את המסמך המצורף</task>
<format>
## תקציר (5 שורות)
## 7 נקודות מפתח
## הנחות וחוסרים
## מה לעשות השבוע (3 פעולות)
</format>
<constraints>ציין אי־ודאות במפורש. אל תמציא מספרים.</constraints>
```
- **כלים:** Claude.ai · Projects (אם מסמכים חוזרים)
- **קושי:** 🟢

### 3. תרגום עם שמירת כוונה (לא מילולי)
- **מה עושים:** מתרגמים EN↔HE תוך שמירת טון ומטאפורות תרבותיות.
- **למה:** תרגום מכונה גולמי נשמע רובוטי; Claude טוב ב־«לוקליזציה».
- **איך להתחיל:** `תרגם לעברית טבעית (לא מילולית). שמור על הומור עדין. סמן בסוגריים מונחים שכדאי להשאיר באנגלית.`
- **כלים:** Claude.ai
- **קושי:** 🟢

### 4. שכתוב לרמות קהל שונות
- **מה עושים:** אותו תוכן ל־3 גרסאות: מנכ״ל, מפתח, לקוח קצה.
- **למה:** חוסך כתיבה כפולה ומחדד מסר.
- **איך להתחיל:** `צור 3 גרסאות של הפסקה. לכל גרסה: כותרת קהל, אורך מקסימלי, ומילים שאסור להשתמש.`
- **כלים:** Claude.ai · Artifacts (להשוואה זה לצד זה)
- **קושי:** 🟢

### 5. עריכת ניוזלטר שבועי
- **מה עושים:** מזינים רשימת אירועים גולמית ומקבלים ניוזלטר מוכן.
- **למה:** מבנה קבוע = פחות חיכוך כל שבוע.
- **איך להתחיל:** הפכו לתבנית Skill או הוראת Project. פרומפט: `מהרשימה הגולמית בנה ניוזלטר: פתיח קצר, 3 כתבות, CTA אחד, PS אישי.`
- **כלים:** Claude.ai · Skills · Projects
- **קושי:** 🟡

### 6. בדיקת בהירות וקריאות
- **מה עושים:** מבקשים ביקורת על טקסט: משפטים ארוכים, מונחים לא מוסברים, כפילויות.
- **למה:** עריכה עצמית קשה; מבט חיצוני ממוקד עוזר.
- **איך להתחיל:** `בדוק בהירות. החזר: (1) ציון 1–10 (2) 5 בעיות עם ציטוט (3) גרסה מתוקנת.`
- **כלים:** Claude.ai
- **קושי:** 🟢

### 7. כתיבת הצעת מחיר / SOW
- **מה עושים:** מפרטים היקף, הנחות, מחוץ להיקף, לוח זמנים ותנאי תשלום.
- **למה:** מסמך שמפחית אי־הבנות מול לקוח.
- **איך להתחיל:** העלו שיחת גילוי צרכים + תמחור בסיס ל־Project. בקשו טיוטת SOW בעברית משפטית־פשוטה.
- **כלים:** Projects · Artifacts (מסמך)
- **קושי:** 🟡

### 8. תיעוד מוצר (Help Center)
- **מה עושים:** הופכים הקלטות/הערות לערכי עזרה עם צעדים ממוספרים.
- **למה:** תיעוד נזנח; Claude מאיץ יצירת בסיס.
- **איך להתחיל:** `הפוך את ההערות למאמר עזרה: כותרת, מתי להשתמש, צעדים, פתרון בעיות נפוצות, קישורים קשורים.`
- **כלים:** Claude.ai · Projects
- **קושי:** 🟢

### 9. עריכת קורות חיים ומכתב מקדים

- **איך להתחיל:** `השווה את הקו״ח ל־JD. טבלה: דרישה | ראיה בקו״ח | פער | הצעת ניסוח.`
- **כלים:** Claude.ai
- **קושי:** 🟢

### 10. פרוטוקול ישיבה → משימות
- **מה עושים:** מהקלטת טקסט/הערות גולמיות יוצרים סיכום + Action Items עם בעלים ותאריך.
- **למה:** ישיבות בלי מעקב = בזבוז.
- **איך להתחיל:** `חלץ החלטות בלבד (לא דיון). לכל משימה: בעלים, דדליין, תלות, סטטוס.`
- **כלים:** Claude.ai · MCP (למשל Slack/Calendar אם מחובר)
- **קושי:** 🟡

### 11. שכתוב אימייל רגיש
- **מה עושים:** מנסחים מייל לדחיית מועמד / תלונה / משא ומתן — בכמה טון אפשרי.
- **למה:** מפחית טעויות רגשיות.
- **איך להתחיל:** `כתוב 3 גרסאות: ישיר, אמפתי, רשמי. ציין סיכונים בכל גרסה.`
- **כלים:** Claude.ai
- **קושי:** 🟢

### 12. Artifact של עורך מאמרים אינטראקטיבי
- **מה עושים:** מבקשים Artifact (React) עם תיבת טקסט, בחירת טון, ופלט משוכתב.
- **למה:** כלי אישי חוזר בלי לפתוח שיחה חדשה כל פעם (**רעיון כללי** לתלוי בגרסת Artifacts/AI-powered).
- **איך להתחיל:** `צור Artifact: עורך טון. קלט טקסט + בחירה (רשמי/חברי/שיווקי). פלט משוכתב + רשימת שינויים.`
- **כלים:** Claude.ai · Artifacts
- **קושי:** 🟡

## 5. תכנות ופיתוח (כולל Claude Code)

### 13. Onboarding לריפו לא מוכר
- **מה עושים:** ב־Claude Code מבקשים מפת ארכיטקטורה, נקודות כניסה, ואיך להריץ מקומית.
- **למה:** חוסך ימים של חיפוש.
- **איך להתחיל:** `סרוק את הריפו. החזר: stack, מבנה תיקיות, איך להריץ, סיכונים, 5 קבצים שכדאי לקרוא קודם.`
- **כלים:** Claude Code
- **קושי:** 🟢

### 14. Code review ממוקד
- **מה עושים:** סוכן/Skill לבדיקת PR לפי רשימת קריטריונים (בטיחות, קריאות, בדיקות).
- **למה:** ביקורת עקבית גם כשעייפים.
- **איך להתחיל:** השתמשו ב־`/code-review` (bundled) או Skill מותאם. הגבילו כלי כתיבה לסוכן ביקורת (read-only).
- **כלים:** Claude Code · Skills · Subagents
- **קושי:** 🟡

### 15. TDD עם סוכנים מופרדים
- **מה עושים:** מחזור RED→GREEN→REFACTOR; כותב הבדיקות לא רואה מימוש, והמממש לא רואה את הספּק המלא — בידוד הקשר.
- **למה:** מפחית «בדיקות שמעתיקות את המימוש».
- **איך להתחיל:**
  1. הגדירו סלייס אנכי קטן.
  2. בקשו: `כתוב בדיקה שנכשלת עכשיו; עצור. אל תממש.`
  3. אחרי RED: `ממש עד שהבדיקה עוברת; בלי לשנות את הבדיקה.`
  4. אחר כך ריפקטור.
- **כלים:** Claude Code · Skills (למשל דפוסי TDD / SKILL.md)
- **קושי:** 🔴

### 16. ריפקטור בטוח עם בדיקות
- **מה עושים:** לפני שינוי גדול — מוודאים כיסוי בדיקות, אחר כך ריפקטור בשלבים.
- **למה:** Claude עלול «לשפר» ולשבור התנהגות.
- **איך להתחיל:** `אל תשנה API ציבורי. הצע תוכנית ב־5 שלבים עם בדיקה אחרי כל שלב.`
- **כלים:** Claude Code
- **קושי:** 🟡

### 17. כתיבת בדיקות חסרות
- **מה עושים:** מזהים פונקציות קריטיות בלי בדיקות ומוסיפים.
- **למה:** רשת ביטחון לפני פיצ׳רים.
- **איך להתחיל:** `מצא 10 פונקציות בסיכון גבוה בלי בדיקות. לכתוב pytest/vitest לכל אחת עם מקרי קצה.`
- **כלים:** Claude Code
- **קושי:** 🟡

### 18. הסבר באג עם ציר זמן
- **מה עושים:** מדביקים לוג/סטאק ויוצרים השערות מדורגות + ניסויים.
- **למה:** דיבוג שיטתי במקום ניחושים.
- **איך להתחיל:** `מהלוג: (1) מה קרה (2) 3 השערות עם הסתברות (3) איך לאמת כל אחת ב־5 דקות.`
- **כלים:** Claude.ai · Claude Code
- **קושי:** 🟢

### 19. יצירת PR description
- **מה עושים:** מסיכום diff יוצרים תיאור PR: למה, מה, איך לבדוק, סיכונים.
- **למה:** סטנדרט צוותי.
- **איך להתחיל:** ב־Claude Code אחרי שינויים: `כתוב PR description בעברית/אנגלית לפי קונבנציית הצוות.`
- **כלים:** Claude Code
- **קושי:** 🟢

### 20. מיגרציית ספרייה/גרסה

- **איך להתחיל:** `הפוך 3 מטרות להרגלים יומיים קטנים + תכנית לחזרה אחרי פספוס.`
- **כלים:** Artifacts
- **קושי:** 🟢

### 105. סידור פיננסי ביתי (בזהירות)
- **מה עושים:** קטגוריות הוצאות, תקציב חודשי, שאלות לבנקאי/יועץ — לא ייעוץ השקעות מחייב.

- **איך להתחיל:** `ארגן את ההוצאות לקטגוריות. הצג אחוזים + 5 שאלות שכדאי לשאול יועץ מוסמך.`

### 106. הכנה לשיחה קשה (משפחה/עבודה)
- **מה עושים:** ניסוח צרכים, גבולות, ומשפטי פתיחה.

- **כלים:** Claude.ai

## 14. מתי Claude עדיף vs מתי ChatGPT עדיף

השוואה **מעשית** (לא אבסולוטית; שניהם משתפרים מהר):

| מצב | נטייה ל־Claude | נטייה ל־ChatGPT |
|---|---|---|
| מסמכים ארוכים, ניתוח מעמיק, כתיבה מובנית | ✅ לעיתים קרובות חזק מאוד | גם טוב, תלוי מודל |
| עבודה על ריפו מקומי עם סוכן קבצים/גיט | ✅ Claude Code אקולוגיה בשלה | Codex/Copilot וכו׳ — תלוי setup |
| Projects עם ידע קבוע + הוראות | ✅ Projects מובנים היטב | Custom GPTs / Projects של OpenAI — חלופה |
| Artifacts אינטראקטיביים בצ׳אט | ✅ חוזקה מובהקת | Canvas/דומים — חלופה |
| Skills כ־`SKILL.md` ניידים בין סוכנים | ✅ תקן Agent Skills צומח | יש מקבילות; אקוסיסטם שונה |
| MCP לכלים ארגוניים | ✅ תמיכה רחבה ב־Claude | גם קיים/מתפתח אצל אחרים |
| תמונות/וידאו גנרטיבי מובנה | לפעמים דרך כלים חיצוניים | ✅ לעיתים אינטגרציה מולטימודלית נוחה יותר |
| חיפוש ווב «סוכן מחקר» כללי | תלוי חיבורים | ✅ לעיתים חוויית browsing חזקה |
| אפליקציות קוליות/מובייל יומיומיות | תלוי אפליקציה | ✅ לעיתים נוח יותר למשתמש מזדמן |
| ציות לפורמט XML / הוראות ארוכות | ✅ מגיב מצוין להוראות מובנות | גם טוב עם מבנה ברור |

**כלל אצבע:** בחרו לפי **זרימת העבודה** (קוד מקומי, Artifacts, Skills/MCP) לא לפי באזז. לשימוש קריטי — בדקו פלט, אל תסמכו בעיניים עצומות על אף מודל.
